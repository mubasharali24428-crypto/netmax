## Blockers for FIX-LOOP : X5

### BLOCKER-1 — Engine over-flags ordinary noise; its own self-check fails
`AnomalyEngineTests.runAll()` prints:
```
[AnomalyEngineTests] FAIL: clean noisy series → []
```
Reproduced independently: on the 20-pt fixture shipped inside the file itself (98–102 Mbps, ±2%), the engine flags idx 4 (97.9 vs expected 99.8, `.notable`) and idx 11 (102.3 vs 100.1, `.notable`). Root cause: rolling-median MAD on smooth low-jitter data yields a tiny spread (MAD ≈ 0.3), so k·MAD ≈ 1 and routine wobble exceeds it. The engine's own oracle declares this series clean; the implementation disagrees. Fix direction (TEAM-2's call): e.g. floor the flag threshold with an absolute epsilon/scale term, widen `k`, or require residual > k·MAD **and** > some fraction of the median level. Whatever the choice, the embedded check must go green.

### BLOCKER-2 — `recentAnomalies` self-check expectation contradicts the function's contract
```
[AnomalyEngineTests] FAIL: recentAnomalies: lookback 5 keeps only the late spike
```
The check spikes idx 2 and idx 14 of a 20-sample series and expects `recentAnomalies(lookback: 5)` → `[14]`. Per the function's own documented semantics ("only anomalies inside the most recent `lookback` SAMPLES"), cutoff = 20 − 5 = 15, so idx 14 is correctly excluded (verified: returns `[]`; control with a spike at idx 17 correctly returns `[17]`). Either the fixture should place the late spike at idx ≥ 15, or the intended product semantics differ and `recentAnomalies` needs rework. Since these blocks convert 1:1 into XCTestCases, shipping as-is hands CI a red suite.
