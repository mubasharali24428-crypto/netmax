### (e) Static audit of identity-present branch — **FAIL (B2, B3)**
Both scripts extract the identity name with:
```bash
sed -E 's/^[[:space:]]*[0-9]+\) ([A-F0-9]+) (.*)$/\2/'     # notarize.sh:96, build_dmg.sh:42
```
`security find-identity -v` prints names **double-quoted**, and this sed keeps the
quotes. Empirically verified that `codesign --sign` rejects a quoted name:
```
$ codesign --force --sign '"-"'
"-": no identity found        # exit nonzero
```
Consequence: the moment a real Developer ID cert exists, `notarize.sh` reaches its
first signing call (`codesign … --sign "\"Developer ID Application: …\""`), fails
with "no identity found", and `set -e` kills the whole pipeline — i.e. the Tier-3
path the entire deliverable exists for cannot complete. Same latent defect in
`build_dmg.sh`'s Developer-ID branch. Reproduced the extraction pipeline verbatim
on a realistic find-identity line: output retains surrounding quotes.

## Blockers

### B1 — README: wrong relative build path, 4 occurrences (README accuracy)
README runs commands from `cd desktop/scripts`; actual output dir is `desktop/build`
(= `../build`). But these lines say `../../build/` (= repo-root/build, which does
not exist — verified):
- L32  `open ../../build/NetMaxDesktop.app`
- L87  `./build_app.sh && open ../../build/NetMaxDesktop.app`
- L162 `spctl -a -vv -t exec ../../build/NetMaxDesktop.app`
- L163 `codesign -v ../../build/NetMaxDesktop-*.dmg`

Every one of these commands fails as written (L162–163 are the "verify like a user"
step of Tier 3). L100 already uses the correct `../build`. **Fix:** `../../build/` →
`../build/` in all four lines.

### B2 — notarize.sh:96 quoted identity name breaks the real pipeline (latent)
Strip the quotes `security find-identity` prints, e.g.
`s/^[[:space:]]*[0-9]+\) ([A-F0-9]+) (.*)$/\2/; s/^"//; s/"$//` (or append
`| tr -d '"'`). Without this, Tier 3 dead-ends at the first codesign call (see
evidence above). Cannot be exercised end-to-end without the paid account, hence
static-audit severity — but it invalidates the "re-run this script after step 5"
promise in both the script header and README.

### B3 — build_dmg.sh:42 same quoted-extraction bug (latent)
Identical fix as B2; otherwise post-notarization re-run (`./build_dmg.sh` picking
up the Dev ID cert) fails the same way and falls back through `|| true` into…
actually worse: the `sed` failure is masked by `|| true`, leaving `DEV_ID` empty,
so the DMG would be **silently re-signed ad-hoc after you just notarized** — the
opposite of documented behavior.
